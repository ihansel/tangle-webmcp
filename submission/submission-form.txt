ABOUT — INSPIRATION
Visual ML tools make pipelines understandable, but agents usually interact with them through brittle clicking and scraping. Tangle already had the right human surface: a real graph, typed components, validation, and undo. We wanted to make that same workspace legible and safely actionable to any WebMCP-capable agent, without replacing the canvas with a private chat protocol or moving the data to a backend.

ABOUT — WHAT IT DOES
Tangle WebMCP lets a person or agent assemble, configure, validate, run, and interpret a curated machine-learning pipeline in the browser. Four prepared stories cover equipment failure, customer churn, customer clustering, and product embeddings. Advanced commerce reports include classifier comparisons, confusion matrices, threshold curves, segment maps, heatmaps, Product2Vec training loss, embedding maps, learned neighbours, and merchandising ideas.

ABOUT — WHY WEBMCP
A graph editor is hostile terrain for coordinate automation: nodes move, ports are small, labels truncate, and screenshots cannot reveal stable task identity or undo state. Tangle registers ten structured, discoverable tools with bounded schemas, stable IDs, named ports, typed results, and explicit errors. This makes compound graph and analysis workflows more reliable than scraping while keeping the capability surface narrow.

ABOUT — BETTER USER EXPERIENCE
The person keeps the visual model. Agent changes appear on the same canvas and use normal undo. A visible panel reports tool availability, local-only execution, state, and the last agent action. An agent cannot start a run until the person grants one-time permission. Results appear as reports that a person can explore rather than an opaque block of agent text.

ABOUT — PEOPLE AND AGENTS TOGETHER
The agent can inspect, search, build, connect, configure, validate, run after approval, and interpret. The person reviews and edits the graph, approves one run, explores the report, and can undo the agent's latest change. Both discuss the same graph and bounded evidence.

ABOUT — HOW WE BUILT IT
We kept the existing React, TypeScript, MobX Keystone, and React Flow editor as the source of truth. A thin adapter reuses Tangle's task, connection, validation, serialization, and undo APIs. A deterministic TypeScript engine runs logistic regression, a small decision tree, K-means, TF-IDF, and Product2Vec inside an ES-module Web Worker. React components render result-specific reports. OpenAI Sites hosts the demo.

ABOUT — WEBMCP IMPLEMENTATION
The editor calls document.modelContext.registerTool for get_pipeline_summary, search_components, add_pipeline_tasks, configure_task, connect_tasks, validate_pipeline, run_browser_pipeline, get_run_summary, inspect_model_metrics, and undo_pipeline_change. Inputs and component IDs are bounded; typed inputs are validated again; mutations share live UI state and undo; runs consume one-time permission and stay in a Worker; summary tools do not return CSV rows. A strict empty-input guard was added locally after review and still needs deployment.

ABOUT — CHALLENGES
We had to expose useful intent-level controls without turning Tangle into an arbitrary code executor; separate editor validity from browser capability; keep derived results useful without returning source rows; make agent-authored graphs readable; preserve static-host deep links; and fit meaningful model reports into the existing product language. Review also uncovered and fixed a local Worker-date mismatch and an empty-input runtime-validation gap.

ABOUT — ACCOMPLISHMENTS
The deployed page exposes ten genuine WebMCP tools. Agent graph changes are visible and undoable. One-run permission works. Product2Vec trained 16-dimensional vectors for 160 products in 71 ms and reduced loss from 0.693 to 0.324; churn compared two classifiers; clustering profiled four customer segments. The synthetic commerce data is reproducible and documented. The review environment passed 2,260 runnable tests.

ABOUT — WHAT WE LEARNED
WebMCP works best as a compact intention-level contract, not a mirror of every UI command. Reusing real application state and undo is more trustworthy than an agent-only copy. Declared JSON Schema still needs runtime enforcement. Browser-local ML is most persuasive when output is both agent-readable and human-explorable.
